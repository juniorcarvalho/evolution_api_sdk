# Plano técnico: envio de texto (`message/sendText`)

Implementar no `evolution_api_sdk` o endpoint de mensagem de texto da Evolution API que chama `{{baseUrl}}/message/sendText/{{instance}}` com body JSON contendo `number`, `text` e opções (`delay`, `quoted`, `linkPreview`, `mentionsEveryOne`, `mentioned`), seguindo os padrões já usados no projeto para `models`, `services` e testes unitários.

## Arquivos e pontos de mudança

- `evolution_api_sdk/models/message.py`
  - Criar os modelos de payload para envio de texto.
  - Funções/métodos esperados:
    - `SendTextMessageConfig.__init__(...)`
    - `SendTextMessageConfig.to_dict()`
    - `QuotedMessageConfig.__init__(...)`
    - `QuotedMessageConfig.to_dict()`
    - `QuotedKeyConfig.__init__(...)`
    - `QuotedKeyConfig.to_dict()`
    - `QuotedContentConfig.__init__(...)`
    - `QuotedContentConfig.to_dict()`
- `evolution_api_sdk/models/__init__.py`
  - Exportar os novos modelos em `__all__` para manter a API pública consistente.
- `evolution_api_sdk/service/message.py`
  - Implementar serviço de mensagem com método de envio de texto.
  - Função/método esperado:
    - `MessageService.send_text(instance_name: str, payload: Union[SendTextMessageConfig, Dict[str, Any]])`
- `evolution_api_sdk/service/__init__.py`
  - Exportar `MessageService` (se o padrão de export público for mantido nesse pacote).
- `evolution_api_sdk/client.py`
  - Instanciar o serviço de mensagens no cliente principal (ex.: `self.message = MessageService(self)`) no mesmo padrão de `self.instance`.
- `tests/test_model_message.py` (novo)
  - Cobrir serialização dos novos modelos e omissão de campos `None`.
- `tests/test_service_message.py` (novo)
  - Cobrir contrato de chamada `client.post(...)`, sucesso e propagação de exceções do domínio.

## Requisitos técnicos de payload

O payload deve preservar exatamente as chaves da API externa (sem normalizar para `snake_case`):

- obrigatórios:
  - `number`: `"{{remoteJid}}"`
  - `text`: `"teste de envio"`
- opcionais:
  - `delay`: `1200`
  - `quoted`: objeto com:
    - `key.id`: `" MESSAGE_ID"`
    - `message.conversation`: `"CONTENT_MESSAGE"`
  - `linkPreview`: `false`
  - `mentionsEveryOne`: `false`
  - `mentioned`: lista com `"{{remoteJid}}"`

Endpoint final no serviço:

- `message/sendText/{instance_name}`

## Algoritmo de implementação

1. Definir estrutura dos modelos de mensagem em `models/message.py` com tipagem explícita e construtores que só persistem atributos opcionais quando `value is not None`.
2. Implementar `to_dict()` em cada modelo para:
   - converter objetos aninhados com `to_dict()` (padrão já usado em `InstanceConfig`/`WebhookConfig`);
   - manter campos booleanos `False` no payload (não tratar `False` como ausente);
   - omitir apenas campos `None`.
3. Implementar `MessageService.send_text(...)` em `service/message.py`:
   - receber `payload` como objeto de modelo ou `dict`;
   - quando houver `to_dict`, converter antes do envio;
   - chamar `self.client.post(f'message/sendText/{instance_name}', data=data)`.
4. Integrar o serviço no cliente principal:
   - importar `MessageService` em `client.py`;
   - criar `self.message` no `__init__`.
5. Atualizar exports de modelos/serviços para facilitar uso público via pacote.
