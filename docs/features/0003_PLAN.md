# Plano técnico: envio de mídia por URL (`message/sendMedia`)

Implementar no `evolution_api_sdk` o endpoint da Evolution API descrito no Postman como **send-media-url**, chamando `message/sendMedia/{instance}` com payload JSON contendo `number`, `mediatype`, `mimetype`, `caption`, `media` (URL do arquivo) e `fileName`, no mesmo padrão já utilizado para `sendText`.

## Arquivos e pontos de mudança

- `evolution_api_sdk/models/message.py`
  - Adicionar modelo de payload para envio de mídia por URL.
  - Funções/métodos esperados:
    - `SendMediaUrlMessageConfig.__init__(...)`
    - `SendMediaUrlMessageConfig.to_dict()`
- `evolution_api_sdk/models/__init__.py`
  - Exportar o novo modelo em `__all__` para manter a API pública consistente.
- `evolution_api_sdk/service/message.py`
  - Adicionar método de serviço para envio de mídia por URL.
  - Função/método esperado:
    - `MessageService.send_media_url(instance_name: str, payload: Union[SendMediaUrlMessageConfig, Dict[str, Any]])`
- `tests/test_model_message.py`
  - Cobrir serialização do novo modelo e omissão de opcionais `None`.
- `tests/test_service_message.py`
  - Cobrir contrato de chamada para `message/sendMedia/{instance}`, sucesso e propagação de exceções.

## Requisitos técnicos de payload

Seguir exatamente os nomes de chaves da API externa (sem conversão para `snake_case`):

- obrigatórios:
  - `number`: número do destinatário com DDI
  - `mediatype`: exemplo `"image"`
  - `media`: URL pública do arquivo
- opcionais (quando informados):
  - `mimetype`: exemplo `"image/png"`
  - `caption`: exemplo `"Teste de caption"`
  - `fileName`: exemplo `"Imagem.png"`

Endpoint final no serviço:

- `message/sendMedia/{instance_name}`

## Algoritmo de implementação

1. Definir `SendMediaUrlMessageConfig` em `models/message.py` com tipagem explícita para campos obrigatórios e opcionais.
2. No construtor, persistir sempre obrigatórios e incluir opcionais apenas quando `value is not None`, preservando possíveis booleanos `False` se a API evoluir com esse tipo de campo.
3. Em `to_dict()`, retornar o payload serializado de forma direta, sem normalizar nomes de chave.
4. Em `MessageService`, implementar `send_media_url(...)` aceitando `dict` ou objeto de modelo; se for modelo, converter com `to_dict()`.
5. Chamar `self.client.post(f'message/sendMedia/{instance_name}', data=data)` mantendo o padrão de serviço “thin”.

- Manter o padrão atual da SDK: modelo responsável por serialização e serviço responsável só por delegar ao client.
- Preservar a nomenclatura da API Evolution (`mediatype`, `fileName`) conforme exemplo do Postman/cURL.
- Não incluir teste de integração nesta entrega; foco em testes unitários conforme solicitado.
