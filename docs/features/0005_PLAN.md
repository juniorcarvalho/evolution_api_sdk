# Plano técnico: envio de áudio narrado (`send-narrated-audio`)

Implementar no `evolution_api_sdk` o request do Postman `https://www.postman.com/agenciadgcode/evolution-api/request/w8l5dk6/send-narrated-audio?sideView=agentMode`, adicionando suporte ao payload no formato solicitado: `number`, `audio` (URL ou base64) e opções `delay`, `quoted`, `mentionsEveryOne`, `mentioned`, `encoding`, seguindo os padrões já usados em `send_text`, `send_media_url` e `send_ptv`, com cobertura por testes unitários.

## Arquivos e pontos de mudança

- `evolution_api_sdk/models/message.py`
  - Adicionar novo modelo de payload para áudio narrado.
  - Funções/métodos esperados:
    - `SendNarratedAudioMessageConfig.__init__(...)`
    - `SendNarratedAudioMessageConfig.to_dict()`
- `evolution_api_sdk/models/__init__.py`
  - Exportar `SendNarratedAudioMessageConfig` em `__all__` para manter consistência da API pública.
- `evolution_api_sdk/service/message.py`
  - Adicionar método de serviço para envio de áudio narrado.
  - Função/método esperado:
    - `MessageService.send_narrated_audio(instance_name: str, payload: Union[SendNarratedAudioMessageConfig, Dict[str, Any]])`
  - Importar o novo modelo junto dos modelos já existentes de mensagem.
- `tests/test_model_message.py`
  - Incluir testes unitários da serialização do novo modelo, incluindo opcionais e campos booleanos `False`.
- `tests/test_service_message.py`
  - Incluir testes unitários do contrato de chamada do endpoint de áudio narrado e propagação de exceções.

## Requisitos técnicos de payload

Preservar exatamente as chaves externas da Evolution API (sem normalizar para `snake_case`):

- obrigatórios:
  - `number`: `"559999999999 (Recipient number with Country Code)"`
  - `audio`: `"https://evolution-api.com/files/narratedaudio.mp3"` (aceitar URL ou base64)
- opcionais:
  - `delay`: `1200`
  - `quoted`:
    - `key.id`: `" MESSAGE_ID"`
    - `message.conversation`: `"CONTENT_MESSAGE"`
  - `mentionsEveryOne`: `false`
  - `mentioned`: lista com `"559999999999 (Recipient number with Country Code)"`
  - `encoding`: `true`

Endpoint final no serviço (conforme você confirmou):

- `message/sendWhatsAppAudio/{instance_name}`

## Algoritmo de implementação

1. Criar `SendNarratedAudioMessageConfig` em `models/message.py` com campos obrigatórios `number` e `audio`, e opcionais `delay`, `quoted`, `mentionsEveryOne`, `mentioned`, `encoding`.
2. No construtor, persistir sempre os campos obrigatórios e adicionar opcionais apenas quando `value is not None`, para omitir `None` sem remover booleanos `False` (inclusive `encoding=False` e `mentionsEveryOne=False`).
3. Em `to_dict()`, serializar o dicionário do objeto e, quando houver `quoted` como objeto (`QuotedMessageConfig`), converter com `quoted.to_dict()`; quando `quoted` já for `dict`, manter pass-through.
4. Exportar `SendNarratedAudioMessageConfig` em `models/__init__.py` para manter o padrão de import público via `from evolution_api_sdk.models import ...`.
5. Em `MessageService`, implementar `send_narrated_audio(...)` aceitando objeto de modelo ou `dict`; converter com `to_dict()` quando necessário.
6. Delegar o envio com `self.client.post(f'message/sendWhatsAppAudio/{instance_name}', data=data)`, mantendo o padrão de serviço "thin" já utilizado no projeto.
