# Plano técnico: envio de PTV (`send-ptv`)

Implementar no `evolution_api_sdk` o request do Postman `https://www.postman.com/agenciadgcode/evolution-api/request/817iqkm/send-ptv?sideView=agentMode`, adicionando suporte ao envio com payload no formato informado: `number`, `video` (URL ou base64) e opções `delay`, `quoted`, `mentionsEveryOne`, `mentioned`, seguindo os padrões já usados em `send_text` e `send_media_url` e com cobertura por testes unitários.

## Arquivos e pontos de mudança

- `evolution_api_sdk/models/message.py`
  - Adicionar novo modelo de payload para PTV.
  - Funções/métodos esperados:
    - `SendPtvMessageConfig.__init__(...)`
    - `SendPtvMessageConfig.to_dict()`
- `evolution_api_sdk/models/__init__.py`
  - Exportar `SendPtvMessageConfig` em `__all__` para manter consistência da API pública.
- `evolution_api_sdk/service/message.py`
  - Adicionar método de serviço para envio de PTV.
  - Função/método esperado:
    - `MessageService.send_ptv(instance_name: str, payload: Union[SendPtvMessageConfig, Dict[str, Any]])`
  - Importar o novo modelo junto dos modelos já existentes de mensagem.
- `tests/test_model_message.py`
  - Incluir testes unitários de serialização do novo modelo e comportamento de opcionais.
- `tests/test_service_message.py`
  - Incluir testes unitários do contrato de chamada do endpoint de PTV e propagação de exceções.

## Requisitos técnicos de payload

Preservar exatamente as chaves externas da Evolution API (sem normalizar para `snake_case`):

- obrigatórios:
  - `number`: `"559999999999 (Recipient number with Country Code)"`
  - `video`: `"https://evolution-api.com/files/video.mp4"` (aceitar URL ou base64)
- opcionais:
  - `delay`: `1200`
  - `quoted`:
    - `key.id`: `" MESSAGE_ID"`
    - `message.conversation`: `"CONTENT_MESSAGE"`
  - `mentionsEveryOne`: `false`
  - `mentioned`: lista com `"559999999999 (Recipient number with Country Code)"`

Endpoint final no serviço (conforme request `send-ptv`):

- `message/sendPtv/{instance_name}`

## Algoritmo de implementação

1. Criar `SendPtvMessageConfig` em `models/message.py` com campos obrigatórios `number` e `video`, e opcionais `delay`, `quoted`, `mentionsEveryOne`, `mentioned`.
2. No construtor, persistir sempre os campos obrigatórios e adicionar opcionais apenas quando `value is not None` para omitir `None` sem remover booleanos `False`.
3. Em `to_dict()`, serializar o dicionário do objeto e, quando houver `quoted` como objeto (`QuotedMessageConfig`), converter com `quoted.to_dict()`; quando `quoted` já for `dict`, manter pass-through.
4. Exportar `SendPtvMessageConfig` em `models/__init__.py` para manter o padrão de import público via `from evolution_api_sdk.models import ...`.
5. Em `MessageService`, implementar `send_ptv(...)` aceitando objeto de modelo ou `dict`; converter com `to_dict()` quando necessário.
6. Delegar o envio com `self.client.post(f'message/sendPtv/{instance_name}', data=data)` mantendo o padrão de serviço "thin" já utilizado no projeto.
